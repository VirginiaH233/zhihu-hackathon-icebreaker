## ⚠️ 写模板的两个坑（每个都真的踩过）

**1. 占位符必须写在正文里，不能只写在 frontmatter。**

`server.py` 取模板时会 `split("---", 2)[2]` **把 frontmatter 切掉**。所以 frontmatter 的「变量:」行里的 `{占位符}` 永远不会被替换。

踩过的：`4c-开场与话题.md` 的 5 个占位符全在 frontmatter → 正文里一个都没有 → `build_opening_prompt()` 的 `.replace()` 全部落空 →
**模型看不到 TA 的名字、看不到灵魂档案、看不到用户的资料库**（模块2「你们可能都感兴趣的」因此恒为空）。不报错、不崩溃、日志干净。

**2. 说明文字里不许嵌占位符。**

`.replace()` 是全局替换：「编号一律指 `{TA 的资料库}` 里的编号」会被替换成**整份资料库**（几千字塞进一句话中间），语义直接崩掉。
要引用就写文字：「编号一律指上面「TA 的资料库」那一节」。

**3. frontmatter 内部不许再出现三条短横线。**

`split("---", 2)` 这行代码本身就是个地雷：**在决策日志里写它**，那三个连字符就把 frontmatter 自己切断了 —— 后半段 frontmatter 会被当成「正文」喂给模型。要提它就写文字（「按三条短横线切掉」）。

**两种渲染机制别混：**

| 模板 | 机制 |
|---|---|
| `4c` | `{单花括号}` → `agent.build_opening_prompt()` 用 `.replace()` |
| `2-分身Agent` | `{{双花括号}}` → `agent._fill()` |
| `1` / `1b` / `4` / `4b` / `5` | 不用占位符，走字符串拼接（f-string）；它们的 frontmatter「变量:」行**只是文档** |

**改完必跑**：`python tests/test_prompts.py`（真渲染一遍，断言数据到位、无残留占位符）。

## 怎么跑对比测试

**链式回归**（一条链路跑到底，每步的真实产出直接喂给下一步 —— 这才是线上真正发生的事）：

```bash
python tests/pipeline.py --list                          # 看有哪些真实答主可当样本
python tests/pipeline.py --a chenqin --b 曾加 --label v1  # 跑完整链路
python tests/pipeline.py --a 许桐楷 --b 曾加 --steps 1,4c # 只跑前两步
```

样本来自 `data/souls/`（产品自己抓的真实答主档案，带 url）——**不手编样本**，编出来的效果等于没测。

**打分**（把「感觉不对」翻译成数字）：

```bash
python tests/score.py logs/pipeline/<某轮产物>
python tests/score.py --compare <A轮> <B轮>     # 两版 prompt 逐指标对比
python tests/score.py --self-test               # 词表自检（正/反样本各一）
```

指标分三组，对应我们的三个目标：

| 目标 | 指标 |
|---|---|
| ① 精准命中、说的是真人想说的 | 引用率、编号有效性、具体性、套话命中 |
| ② 有满足感 / 不出戏 / 不鸡对鸭讲 | 平均字数、问句数、AI 腔、自指逃生口、反应率 |
| ③ 有分享欲 | 评论的具体性、独立可读性 |

## 四条判断标准

评判任何一版 prompt，逐条对照：

| 标准 | 怎么判 | 失败长什么样 |
|---|---|---|
| **有洞察** | 看完能不能发现「我没注意到的点」 | 「TA 是个认真的人」 |
| **不套话** | 通篇有没有假大空的形容词 | 「很有见地」「值得欣赏」 |
| **依据可见** | 每个判断能不能指出为什么（引原文） | 直接给结论，没有依据 |
| **可行动** | 产出能不能直接被用上 | 「多交流」 |

## 一条铁律

**有据才说。** 检索到依据就标注出处；检索不到就诚实说「TA 好像没写过这个」——这是产品的正常输出，不是失败。
